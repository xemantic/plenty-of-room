## The problem, restated

`C-0073` Part 4 audited `P-18`'s rounding propagation with

```
grep 'File("gpd/results/'
```

and concluded *"the propagation closes (here `T-1d` has one reader, `T-1f` and `T-2` none)"*.

`CH-0092` (upheld, iteration 15) found the census wrong: `T-1d` has **three** readers and `T-1f`
has **two**. The two missing edges run through `window/ResynthesisInputs.kt`, which assembles its
paths as `File(directory, "T-1d-scf-density-profile.json")` while its two callers pass
`File("gpd/results")` — **a grep for the literal directory finds two call sites that name no file,
and a grep for the literal filename finds a call site that names no directory.** Neither search
finds the edge. `T-25` and `T-118` therefore stood for a whole iteration built from stale
nine-digit inputs; 325 and 2 751 of their fields moved when re-emitted.

The defect is not in the code. It is in the **instrument**: an audit is only as complete as the
shape of the search that performed it, and this repository's audits are performed by hand.

## Numeric target and acceptance predicate

**Acceptance** (as registered in `TASKS.md`): *every study's set of input result files derived from
the source rather than grepped, and asserted as a test.*

**Falsifiable predicates.**

1. **P1 — the derivation finds the edges a grep cannot.** The derived census must contain the two
   edges `CH-0092` names — `WindowResynthesisStudy` and `SecondResynthesisStudy` reading `T-1d` and
   `T-1f` — and must report `T-1d` with **3** readers and `T-1f` with **2**. If it reproduces
   `C-0073`'s 1 and 0, the derivation is a grep in different clothing and the task has failed.
2. **P2 — prose is not a read.** Twenty-odd source files *mention* a result file in a KDoc comment
   or in a `findings`/`source` string (`"read from gpd/results/T-130-*.json"`). None of those is an
   `open`. A census that counts them is worse than the grep, because it over-reports and therefore
   cannot be used to certify that a propagation closes. The census must classify by **syntactic
   position** — a string literal in the argument list of a `File(...)` construction — not by
   substring.
3. **P3 — the `sources` convention is measured before it is rested on.** `CH-0092` observes that
   `WindowResynthesisStudy` declares its inputs in a `sources` parameter and that the fact was
   therefore already in the repository. **How many studies do that is an open question and this
   task must answer it**, because the test the acceptance predicate asks for — *declared equals
   read* — covers exactly the studies that declare. If the convention is not universal, the task
   says so and says what the test can and cannot cover.
4. **P4 — the check is executable and it is invoked.** A census emitted once is `C-0073`'s grep
   with more steps. The check must run without an agent remembering it (`C-0078`: *a check nobody
   remembers to ask for is not a check*), and it must fail on a real regression. Its own falsifier:
   introduce, in a fixture, a study that reads a file it does not declare and a study that declares
   one it does not read, and require the check to fail on each.
5. **P5 — the instrument does not break the harness it is wired into.** Two other agents run
   `tools/verify.sh` against this checkout during this iteration. The edit must be additive,
   opt-out-able, and proved by a full-suite run through the edited script.

## Conventions, fixed before deriving

- A **study** is a Kotlin main source containing a top-level `fun main(`.
- A **result file** is a file under `gpd/results/`; a **result-file literal** is a string literal
  matching `[TP]-<id>-<slug>.json`, with or without a `gpd/results/` prefix.
- A **read edge** `study → file` exists when the study, **or any main source reachable from it
  through top-level declarations**, constructs a `File(...)` whose argument list contains that
  result-file literal, and the constructed file is not the one written.
- A **write edge** exists when a result-file literal is constructed as a `File` that is written —
  directly (`File("…").writeText`) or through a local `val` that is (`val output = File("…")` …
  `output.writeText(`).
- **Reachability** is over Kotlin *files*: file `A` reaches file `B` when `A` references, outside
  comments and string literals, an identifier declared at top level in `B`, and `B` is in `A`'s own
  package or is imported by `A`. This is deliberately **over**-inclusive: a false extra edge
  over-reports a reader, which is the safe direction for an audit whose purpose is to certify that
  a propagation *closes*. The census reports direct and transitive edges separately so the
  inclusion can be audited.
- The census is a statement about the **source tree**, not about a run. Nothing here executes a
  study.

## Plan — the cheap bound first, and what would falsify the approach

**The cheap bound is a hand count, and it is already published.** `CH-0092` gives the corrected
census for three files (`T-1d`: 3, `T-1f`: 2, `T-2`: 0). That is the fixed point the derivation
must hit before anything else is believed about it, and it costs nothing to check. A second free
cross-check: the repository contains 72 studies and 72 result files, so a census in which some
study writes no file, or two studies write the same file, is wrong on its own arithmetic.

**Why static analysis rather than instrumentation.** The alternative — run every study under an
`open()` trace — is exact and costs days: `T-1d`'s sweep alone is 33 minutes and several studies
are longer. The census is needed *before* a re-emission, to decide whether to pay for one, so a
method that costs more than the re-emission it is auditing is not a method. Static analysis over
~180 main sources costs under a second and is re-runnable on every verification.

**What would falsify the approach.**

- If the reachability closure is so over-inclusive that most studies appear to read most files, a
  file-level call graph is the wrong granularity and the census would have to be built at
  declaration granularity (or from a real Kotlin parser). The measurement that decides it is the
  count of transitive-only edges; if it is comparable to the number of direct edges, the approach
  has failed.
- If more than a handful of studies construct their input paths in a way no syntactic rule can
  follow — a name computed at run time, a path read from a configuration — then no static census is
  complete, and the honest deliverable becomes a census plus an explicit list of the call sites it
  cannot resolve.
- If `sources` turns out to be declared by nearly every study, the whole census is redundant and
  the cheap form in the acceptance predicate is the whole answer.
